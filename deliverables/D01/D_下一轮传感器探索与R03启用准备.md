## 一、下一轮数据方案

配置为 configs/research/sensor_benchmark_next.draft.json：32 个新源 episode，每条60步，计划1920次成功step。训练8条全程无人工污染；验证和保留测试各12条，其中6条全程无污染、6条有明确传感器偏置。训练/验证/测试种子区间分别16001—16008、17001—17012、18001—18012；不复用上一轮episode充当新增独立数据。

故障只在环境step成功后修改投递 observation[6]，不改变环境状态或动作。预定6种组合覆盖不同起点、持续时间及0.80—1.20的乘性偏置，正负方向均包含。验证/测试使用同类预声明机制但独立源环境，不能据此声称未知故障类型泛化。所有物理健康标签保持null；未污染仅指没施加声明的人工传感器污染。

原始干净/投递/派生或重放视图继承同一来源组，不可跨划分；回放副本不计新独立episode。采集后还必须核验初态/完整轨迹哈希、连续状态/终止、请求与实际动作，以及注入逐点一致性。不同种子不是统计独立性的证明。

```bash

```

计划执行与算力预算待B确认，collector_review_ref和budget_confirmation_ref当前为空。校验通过只说明方案结构一致，输出仍data_collected=false、execution_authorized=false；没有偷偷开始仿真。

## 二、探索入口

l3_system.monitoring.sensor_exploration 接受原始39维投递观测的完整train/validation episode列表。每项需要episode_id、lineage_group、split、observations、labels、label_scope、label_source；labels必须逐记录显式布尔，scope只能sensor_fault或synthetic_fixture，禁止改成物理健康标签。只接收传感器未污染训练，验证必须同时具有整条未污染对照和有注入的轨迹。

输入含test分组会直接报错，包括没有标签的test记录；不自动过滤后继续。既有review_r03_supplement的输出是38维投影，不能直接传入本入口。须从受核验来源构建原始39维train/validation输入，保留正确分组和标签；不得把上一轮test改名为validation后继续声称原测试独立。

示例配置 configs/research/sensor_exploration.example.json 给出8个候选：窗口4/8，完整统计/变化统计两组，非时钟索引1—38/E-factor索引5和6两种投影。统计项可选择mean/std/min/max/delta/absdiff；禁止将原始索引0、元数据或标签作为特征。树数100、随机种子1511是可复现工程设定；运行网格有上限。

每个候选独立在训练集拟合StandardScaler与IsolationForest。在验证集所有无污染窗口中约束FPR预算（示例5%），再按recall、precision和更高阈值决定阈值；没有报警的候选也可合法获选，recall为0会如实报告。FPR预算不是概率校准或物理限值，也不等于整条episode误报率，所以另报告整条未污染验证episode及出现报警的条数。

候选模型选择仅使用验证结果。多次网格选择会对验证集乐观，必须冻结选项后另取全新测试一次评估；本轮没有在真实旧数据上运行网格，也没有产生新的真实效果结论。窗口长度不同会排除不同预热记录，报告窗口数，不能隐藏预热不可评分状态或直接把该网格排名称为公平部署收益。

```bash
python -m l3_system.monitoring.sensor_exploration \
  --episodes /path/to/reviewed-train-validation-only.json \
  --config configs/research/sensor_exploration.example.json \
  --output /path/to/new-private-exploration.json
```

输出仅探索配置、验证计数、选择理由、输入字节指纹及依赖版本，不导出部署权重或开启模型。输入和结果含数据来源信息时保持私有；本次GitHub只含代码、通用方案和合成测试。合成夹具上已实际拟合全部8候选，并检查误报预算、时钟排除、跨划分重复轨迹和test拒绝。

- 阻断/接管处置、恢复条件、可信新鲜状态契约。
- 边界测试记录和回退版本。

实际启用按以下顺序进行，当前停在待确认阶段：

1. A/团队确认比例R、允许工况、参考定义和处置/恢复，B核对配置/单位/源坐标。mAb不套用此Atropine规则。
2. D/A在固定版本中完成相对参考比较与可信上下文的实际门禁接线。现有通用过程围栏不等于此候选已注册；当前main CLI也没有通用`--process-rules`加载开关，不能编造一条开启命令或仅改enabled=true。
3. 单元与集成验证：阈值等于不触发、稍超触发；参考≤0、阈值被裁剪遮蔽、缺字段/错误单位、配置变化或旧状态均不能默认通过。通用可观测性条件为0<参考且(1+R)×参考<20，20仅裁剪天花板，不是工艺安全限值。
4. 分别验证前置门禁和post-step观测：已发生动作不能追溯撤销，post-step命中只能影响后续自动周期。人工恢复确认不直接放行动作，下一候选仍经过D；真实生产目标和允许范围不能由模型yss替代。
5. 在隔离仿真中做版本化验收，固定配置、规则依据和日志，核对风险阻断、资源清理、无重复step、未知执行结果不重试。取得真实测试记录后再进行显式版本化启用，不由此草案代替。
6. 回退采用经核验的旧配置/版本，停止后续自动周期并保留审计记录，R01/R02不随R03回退关闭；已发出的未知结果不得重发。不把回退当作恢复工艺健康的证明。
