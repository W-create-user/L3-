# D02 工艺规则与运行围栏

2026年11月12日。本次交付可配置规则引擎及审核链集成；Atropine 和 mAb 的物理阈值尚未验收，仓库默认配置保持关闭。本实现用于仿真围栏，不是工业安全控制器。

## 已实现能力

| 规则类型 | 判断 | 数据要求 |
|---|---|---|
| range | lower ≤ 当前值 ≤ upper | 变量索引、单位、坐标、范围依据 |
| rate | 候选动作与上次已执行动作差值绝对值除以间隔秒数 ≤ 最大变化率 | 同一episode的上次已执行动作及两次动作时间 |
| precondition | 指定观测或动作值等于预期数值 | 已核验的数值前置条件；只在候选动作审核时检查 |
| freshness | 审核时间减观测时间 ≤ 最大有效时长 | 同一时钟中的有限秒数；未来观测时间拒绝 |

运行顺序保留现有 STATE-INVALID、R-01、R-02，再执行已启用的工艺规则。规则全部是阻断检查；不存在高模型分数放行的路径。多个规则同时触发按 priority 升序、rule_id 字典序记录全部结果；同一变量的互斥范围或前置条件在配置阶段拒绝。缺少上下文、单位/坐标不符、环境不符、上一动作来自其他episode或时钟无效时触发 R-03-CONTEXT。

每个规则单独有 enabled、rule_id、priority、basis 和 suggestion。basis 包含来源类别、引用、复核人、复核日期。支持 model_definition、authorized_rulebook 与 team_experiment；团队实验阈值还要求构造时显式 allow_experimental=True。引擎验证这些字段及数值，不会访问来源链接或证明签字真实性；物理依据仍需 B 与 D 审阅，不能把填写来源字段当作已验证。

状态范围和新鲜度在执行后状态核验、接管恢复中仍检查；动作变化率及前置条件用于下一候选动作审核。人工确认只允许尝试恢复，不执行动作，也不豁免下一候选的完整审核。D05 的置信度校准、迟滞与保持时间不在本次实现范围。

## 接入方式

规则引擎位于 [process_rules.py](../l3_system/agents/process_rules.py)，经 [monitoring_agent.py](../l3_system/agents/monitoring_agent.py) 接入既有审核入口。现有 run_control_cycle 可以接收此 monitor；main 的 r03_enabled 摘要根据真实配置报告。

```python
from l3_system.agents.process_rules import ProcessRuleEngine
from l3_system.agents.monitoring_agent import MonitoringAgent

rules = ProcessRuleEngine.from_json('configs/safety/atropine.disabled.json')
monitor = MonitoringAgent(
    action_space=adapter.action_space,
    observation_space=adapter.observation_space,
    process_rules=rules,
    process_context_provider=build_verified_context,
)
```

adapter 和 build_verified_context 由调用方提供，上述是接入示意，不是独立启动脚本。默认 [atropine.disabled.json](../configs/safety/atropine.disabled.json) 不包含任何物理阈值，不启用 R-03；39维观测和4维动作对应当前 Atropine 默认配置的静态接口信息，不能代替 B03 的逐维物理字典。mAb 没有默认配置，不能套用 Atropine 形状或阈值。

启用配置必须填写准确的 observation_shape/action_shape、variables 和 rules，并与实环境空间匹配。variables 每项包含 source（observation/action）、展平后的 index、unit 和 coordinate。规则完整字段见 [测试配置函数](../l3_system/tests/test_process_rules.py)；其中 environment=SYNTHETIC_TEST_ONLY 且所有限值仅为单元测试设定，不能直接用于过程运行。

## 上下文契约

provider 每次审核调用一次，签名为 provider(observation, action)，返回字典。action=None 表示状态检查。输入使用副本，provider 不应推进环境或更改状态。配置 provider 时它的结果优先，请求不能通过 safety_context 覆盖。未配置 provider 时 check_request 接受 safety_context；这仅用于可信调用方，不能让不可信前端自行申报单位、时钟与来源。

| 字段 | 含义 |
|---|---|
| environment / episode_id | 当前环境及episode身份 |
| variables | 参与已启用规则的每个变量的 unit 和 coordinate |
| reviewed_at / observed_at | 同一时钟内审核及观测时间，单位秒 |
| action_at / previous_action_at | 计划动作与上次已执行动作的时间，单位秒 |
| previous_action | 上次真实执行的动作向量，不能用上次被拒绝的候选代替 |
| previous_action_episode_id | 必须等于当前episode，reset后不可沿用旧动作 |

首次动作没有上一执行动作时，rate规则保守拒绝；需要 B 给出有依据的初始化控制量及其生效时间，或按批准的初始化协议单独处理。provider 必须从唯一执行端获取这些数据；本次未自动从上游猜测初始动作或采样周期。

单位/坐标比较验证的是声明一致性，不能自动证明实际数据已经按所声明方式转换。时间戳必须由可信采集方提供；比较数值本身不能验证两台机器是否同步。多进程时钟同步和传输延迟处理须与 C04 的通信契约一起验收。

## 验证与当前缺口

新增测试使用 FakeAdapter 和合成变量。覆盖边界、两侧越界、缺失、非有限值、错误单位、变化率、前置条件、新鲜度、规则冲突、最终审核、来源日志和接管恢复。测试可以证明契约和阻断路径，不证明真实 Atropine/mAb 工况安全、检测准确率或生产效率。
