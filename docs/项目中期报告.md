# 面向流程工业四类智能体协同系统中期报告

核验日期：2026年11月6日。项目名称依据计划书正文为“面向流程工业L3级自主运行的智能体集群多模态监管与协同执行研究”。本报告以用户提供的计划书与原中期报告为范围依据，以仓库实际代码和本次运行记录为完成依据。计划中的指标、预算及未来功能不作为已经取得的实验成果。

## 项目阶段性成果总结

### 1 已形成四类智能体互联的本地同步原型

建立仓库根目录 main.py 统一入口，调用仓库中的实际 DecisionAgent、SchedulingAgent、ExecutionAgent 和 MonitoringAgent。A 通过有限模板产生带任务编号、子任务编号、顺序和依赖的任务；C 按依赖就绪状态进行公告、投标校验、加权评分、分配和反馈；B 生成候选并执行经过审核的动作；D 使用真实模型动作空间审核候选。最终状态由新增的 A 反馈适配层接收并核对原任务和全部子任务编号。

这属于单进程 Python 函数调用的协同原型，已经实现四类角色的数据闭环，不等于部署了四个网络进程，也不等于工业 L3 自主运行已经达标。仓库 A 原模块只有模板任务生成方法，因此状态有效性检查、结果核验和反馈收件由本次集成层补齐；不将这些功能描述为 A 原代码已实现的大模型推理。

### 2 已建立完整任务依赖调度链路

控制任务包含 collect_observation、evaluate_goal、generate_action_intent、safety_review、execute_approved_action、verify_result 六个步骤。每个步骤均保留原 subtask_id，作为独立调度节点交 C 处理，只有前置子任务完成后才参与分配。主程序核对 winner_id、任务编号、子任务编号与 C 的活动资源锁，终态反馈后检查锁已释放。失败后下游依赖保持未执行，不伪报总任务完成。

C 的权重为能力0.50、成本0.30、负载0.20，是原型配置参数。本次每种能力只有一个合法候选角色，estimated_cost=1.0 为配置的单位成本、capability_match=1.0 为能力匹配指示，load=0 为同步空闲状态。这些投标不是测得的工业成本或预测准确率；目前不足以验证多执行者竞价的优势。

### 3 已建立独立审核与执行门控

仓库根目录实际 D 模块提供 check_action(state, candidate_action)，当前尚无 check_request。新增 MonitoringGateway 将其适配为 check_request(request, observation)，保留 D 原始返回值；不把历史交付快照与仓库当前模块混用。D 以真实 adapter.action_space 初始化，demo_mode=False。

候选准备阶段不推进环境；审核通过后，B 再核对请求内容、请求编号、状态版本和审核关联后执行。R-02 拒绝时不调用 step。监管缺失、未知决定、任务错配、矛盾结果或监管异常均阻断；C 接收失败原因，A 收到最终任务状态。D 的 R-01/R-02 属于输入及模型动作边界检查，R-03 状态规则在本次代码中未启用。

### 4 已形成 AtropineEnv 真实仿真闭环

本次运行环境为 Python 3.11.18、SMPL AtropineEnvGym，39维观测、4维动作，normalize=False、uss_subtracted=True。动作空间从模型实时读取；SMPL 固定版本见执行智能体目录中的 SOURCE_VERSION.json，依赖见 requirements-lock.txt。

动作中点仅用于接口测试。它读取模型动作空间并形成有限合法候选，不是最优控制器，也不是 PID、强化学习或状态反馈优化。步长、数值积分、reward 和观测来自真实模型。旧版 done/timeout 对 terminated、truncated 的映射由适配器记录，不把采集器停止当成模型截断。

计划书以 mAbEnv 为主要研究对象、AtropineEnv 为辅助验证环境。本阶段先在 AtropineEnv 验证工程闭环，是实施顺序调整，不是已经完成 mAbEnv。尚未证明跨工序的单抗生产协同控制。

### 5 已完成具有明确口径的阶段实验

最终代码的原始结果位于 evidence/four_agents；第一次实验另存于 evidence/four_agents_initial，两批不重复统计。最终批次对 seed 1101、1102、1103 分别运行单执行模块基线与四类智能体系统，固定相同中点动作、相同环境和初始种子。正常四智能体任务3次均完成，每次真实推进1步；基线也各推进1步，本批真实执行合计6步。

三组配对中 reward 差值和执行后 E-factor 差值均为0，说明编排没有改变所选动作对应的模型结果。单执行模块基线保留 D 的相同审核，取消 A/C 编排，故此实验是架构开销和一致性检查，不是单一控制算法与协同优化算法比较。耗时包含模型构造之后的各模式初始化、reset及单次任务流程，不含模型构造，受机器状态和日志开销影响。实测四角色路径耗时更长，不能据此声称效率提高20%。

另运行3次真实四角色越界候选任务，均触发 R-02，真实 step 增量均为0；运行一次三步“检查状态”任务，完成且 step 增量为0。这些有意拒绝用例不计入正常任务完成率。

监管开关比较采用40个离线候选：20个模型边界内动作与20个明确越界动作。启用监管时分别20/20放行、20/20拒绝；不启用监管仅记录“将绕过审核转发”的逻辑结果，没有把越界动作送入环境。这里的标签仅表示模型输入边界合法性，不是经工艺专家认定的危险标签；不能称为工业危险拦截率或证明异常工况检测有效。

固定 first-fit 与 CNP 的30组对照仍采用仓库 C 模块原有的确定性合成 Bid 数据。该材料可以说明评分机制行为，不支持真实 SMPL 的效率提升结论。本次没有生成虚构的额外执行者来扩大比较样本。

最终新增8项真实环境集成测试通过，覆盖正常六步依赖及编号、R-02拒绝、只读任务、监管缺失、未知决定、任务错配、矛盾结果和监管异常。既有 C 的16项测试与 B/A/D 合并回归的59项测试也通过。不同测试套件的用例不能直接当成独立工业场景数量。

### 6 已保留可复查工程资料

每次系统运行保存 A_task.json、A_feedback.json、result.json、events.jsonl、B_events.jsonl 与 transitions.csv。事件中包含 Bid、Assignment、D 原始审查、B 反馈和 C 状态更新；CSV保存实际执行的动作、观测、reward、终止标志和 info。拒绝或只读运行的转移 CSV 只有表头，因为没有真实 step，不伪造数据行。

配对原始数据见 single_vs_four.csv，离线监管样本见 monitor_offline.csv，汇总见 summary.json，曲线见 single_vs_four.png。源代码 SHA-256 和输入文档哈希用于追溯版本。此前 B 的900步轨迹是另一阶段的数据，不作为本次六步实验的新采样，也不用于声称四角色已连续执行900步。

## 项目进展状况小结

项目已从模块独立开发推进到四类智能体本地闭环和初步重复验证阶段。新增统一主程序与适配层能够把 A 的实际任务生成、C 的实际调度、B 的真实模型执行、D 的规则审核组织到同一任务生命周期中，保留原始标识和失败反馈。当前可展示“目标输入—模板分解—依赖调度—候选准备—监管—执行—结果回传”的可运行过程。

已完成内容集中于工程架构、接口和确定性安全门控。计划书提出的多模态融合、mAbEnv、置信度评估、人工接管、MADDPG、扰动/传感器模型等方向仍需研究，不因四角色已互联就宣称全部完成。本阶段没有工业性能达标、论文发表或软件成果授权的核验证据。

## 项目今后计划

第一阶段，扩展真实控制策略与工作负载。对任务生命周期补充严格的超时、失联、恢复和重复回执幂等性，加入多个真实执行者与公平的成本估计，再做固定调度与 CNP 对照。并发、跨进程运行与动态负载均不能由当前同步实验外推。

第二阶段，在导师确认的模型、状态含义、物理单位与阈值依据下开发 R-03；将数值观测、设备文本事件和后续真实视觉数据接入统一带时间戳接口。在有标注数据、训练/验证分离和误报评估之前，不对模型异常检测能力作结论。

第三阶段，按计划书推进 mAbEnv 主研究对象的环境评估与适配，建立可比较的上下游任务、状态和动作协议。扰动和传感器误差应以明确模型与参数实现，并单独标记数据来源，不能把越界候选等同于过程故障。

第四阶段，建立有依据的运行围栏、人工接管请求和人工确认恢复状态机。当前失败反馈只能表示软件阻断，不等于真实装置紧急停车或人机接管已实现。

第五阶段，围绕统一任务集和控制基线扩展重复次数，分别评价架构开销、调度效果、控制质量与监管性能。性能提升必须由对应对照数据支持，不能从“多了几个角色”推导优化收益。论文和软件著作权仍作为后续计划，实际进展另凭凭证确认。

## 项目仍存在的问题及解决方案

### 一 系统稳定性与失败生命周期

当前为同步单进程、有限模板原型，模块异常会反馈失败并停止后续依赖。尚未验证多线程/多进程一致性、重复消息、进程重启、强制超时取消和长时间运行。后续增加幂等请求、持久化任务状态、显式恢复和超时责任边界，不把未知结果当作成功。

### 二 规划与调度的研究深度

模板规划不具备开放目标推理能力，单合法候选的调度不能体现多执行者协商优势。未来需增加真实任务和真实执行者，固定相同候选集合开展公平比较；权重搜索与敏感性分析必须同训练/评估数据划分一起设计。

### 三 控制策略与模型范围

中点策略仅用于接口合法性验证，无目标跟踪或能耗优化。mAbEnv、PID/MPC及学习控制器尚未完成。后续先定义可衡量工艺目标和约束，再开展控制基线与策略比较，不在已有模型上随意修改方程来获得期望结果。

### 四 多模态与工艺安全依据

本次没有真实图像、视频或企业DCS数据用于融合训练，不能宣称已形成多模态检测模型。动作 Box 和经验样本范围不等于工业安全阈值。需要先获得数据和专家依据，再确定监管规则及误报/漏报评价。

### 五 人机协同与L3边界

当前可以阻断动作并返回原因，尚无实际操作员接管/确认恢复流程和工业安全论证。应通过仿真建立状态转换、权限、确认和审计流程，再讨论人高于环的实验验证，不能直接宣称L3达标。

### 六 实验充分性

n=3的匹配单步实验与40个已知边界离线候选只能支撑小范围工程结论；没有统计显著性、泛化或长期稳定性证据。不启用监管的对照仅为离线决策，不是危险输入的真实无监管执行。后续根据研究问题定义样本量、种子、工况、基线和指标，并保留失败案例。

一键脚本已在 Windows PowerShell 下分别验证 normal、reject、inspect 入口。检查中发现并修正了中文路径 UTF-8 BOM 问题，初始失败日志与修复后日志同时保留；这些入口试运行不混入上述最终批次六步计数。
