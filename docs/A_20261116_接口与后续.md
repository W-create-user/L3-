# A02/A03/A04 接口与后续集成

## 字典和目标评价

`python -m experiments.build_a_registry` 从已公开 B 字典的固定字节副本构建 Atropine 模型注册表。副本在 configs/goals/sources，源提交与字节哈希在构建器中固定。模型 Box 不是工艺安全阈值；四个动作轴使用 delta_from_USS 坐标，单位保留来源推断限定；不确定观测字段被排除。没有 mAb 可用目标字典或默认生产目标。

`evaluate_goal(observation, history, goal, registry)` 返回 status、achieved、in_range、deviation、consecutive_steps、remaining_steps、reason。无效 GoalSpec 抛出 ValueError；样本无效返回 unevaluable，不能成功。

样本字段为 goal_id、environment_id、registry_version、episode_id、step、observation、safety_ok。history 是同一不可变目标、同一 episode 的完整较早样本，从 step 0 或1开始，步号必须连续。step 0 是 reset，不计保持窗口。改变目标需要新 goal_id；本接口暂不提供中途目标修订的历史迁移。safety_ok 必须由调用方明确提供，并不表示评价器已认证真实工艺安全。reward 不参与目标评价。

## 有限 HTN

`DecisionAgent.create_goal_plan(goal, registry, observation, history, capabilities=...)` 返回 GoalPlan：

| 方法 | 条件 | 路径 |
|---|---|---|
| adjust_target | 未达目标区间 | 评价、选择调整策略、生成候选、审核、执行、复核 |
| hold_target | 区间内但保持窗口不足 | 评价、选择保持策略、生成候选、审核、执行、复核 |
| report_achieved | 已满足保持条件与步预算 | 只读目标复核，无物理动作 |

未知/失败状态或缺失资源能力停止规划。GoalPlan.validate 检查重复节点、缺失依赖、依赖环；ready_tasks 根据布尔事实与已完成依赖返回就绪原子任务；verify_completion 要求外部完成证据后才返回软件符号效果。效果不表示化学状态必然变化。

此入口只生成计划，不直接执行模型。旧 create_task/main 执行契约继续保留；新数值目标的物理调度路由属于后续 A05，需要 B 控制基线和 D 围栏确认。

## 六类失败与恢复

| 类别 | 处理 |
|---|---|
| candidate_rejected | 明确未调用 step、未执行，且有剩余预算才允许再生成候选；本地会话还检查锁释放和待执行请求 |
| no_resource | 明确未执行、释放确认及实际无活动锁、有预算才允许 C 重派 |
| message_timeout | 与上项相同；超时文本本身不是未执行证明 |
| execution_result_unknown | 不自动重放；返回对账/接管要求 |
| environment_error | 不自动重试物理执行 |
| unknown_state | 保守接管，不按错误文本猜测执行事实 |

ReplanningController 与本地会话共用分类。后继结果保留 parent_plan_id/root_plan_id 和历史失败计划；候选重试计数绑定根计划。分类器本身没有实现跨进程对账。

## 仍需交接的输入

- B：生产目标变量、可达范围、控制基线、mAb 逐变量单位/索引与终止语义。
- D：有来源并明确批准状态的工艺围栏。未确认前 R-03 保持关闭。
- C：带关联 ID 的取消/释放确认、超时及迟到反馈协议。
- A：17—18日继续目标生命周期预算/截止时刻、受限重规划与真实目标验证；A05 接入数值目标路由。

这些输入没有被本轮代码代替。工程接口完成不表示生产目标、工艺安全或全部研究指标验收完成。
