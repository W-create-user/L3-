# 四智能体系统集成与恢复

依据项目实施方案修订稿的近期工程范围，保留本地同步消息调用和 AtropineEnv。
四角色仍为 A 决策、C 调度、B 执行、D 监管。`python main.py --cycles 5`
现在在同一个 `MultiAgentSystem` 会话内运行，保留调度任务、锁、反馈和状态历史。

## 本次修复

- A 的父任务依赖原先在转换时丢失，现在传给根子任务，由 C 检查。
- 每条编排事件附带父 task_id，子任务继续保留 subtask_id，候选动作保留 request_id。
- D 可绑定真实 observation_space，在动作放行前核验观测的维度和有限数值；
  执行后独立复核最新观测。`STATE-INVALID` 是数据完整性检查，不是 R-03 工艺异常模型。
- 最终门控拒绝统一报告 `safety_rejected`，不会误报为一般执行失败。
- 连续运行复用智能体实例；拒绝/异常进入持续接管状态，后续调用无法自动越过。
- 未实现的父任务前置条件、工艺约束和自定义完成判据会明确报错，不再静默忽略并报告完成。

## 状态与恢复

| 状态 | 含义 | 出口 |
| --- | --- | --- |
| autonomous | 允许提交下一轮任务 | 正常完成后维持，拒绝/错误后退出 |
| restricted | 仅允许生成并重新审核替代候选动作 | 审核后完成则自主，次数耗尽则请求接管 |
| takeover_requested | 阻断新周期 | 人工确认且环境就绪、观测有效、资源锁释放后恢复 |

有限重生成默认关闭。启用时，仅对 `safety_rejected` 且 `step_delta == 0`
的结果重新规划，调用方必须提供支持 attempt 参数的候选生成器。
每次重规划生成新的任务/请求 ID，旧失败计划保存在 recovery_attempts 中。
环境 step 已被调用、模块异常、监管异常均不自动重试，防止重复执行未知结果的动作。
每个控制周期仍执行至多一个成功动作。

```python
from l3_system.execution import EnvironmentAdapter, ExecutionAgent
from l3_system.agents.monitoring_agent import MonitoringAgent
from l3_system.runtime import MultiAgentSystem

with EnvironmentAdapter(max_steps=60) as adapter:
    executor = ExecutionAgent(adapter, log_path='outputs/session/B.jsonl')
    executor.reset(seed=1101)
    monitor = MonitoringAgent(adapter.action_space, adapter.observation_space)
    system = MultiAgentSystem(executor=executor, monitor=monitor,
                              event_path='outputs/session/events.jsonl')
    result = system.run_cycle('执行一次仿真控制任务')
    # 如进入 takeover_requested，人工查明原因并修复后显式调用：
    # system.resume(operator='实际操作人', reason='实际处置说明')
    # 如环境已结束/损坏，明确开始新的仿真 episode：
    # system.resume(operator='实际操作人', reason='重新初始化仿真', reset=True)
```

`resume` 本身不执行控制动作；不带 reset 时不会偷偷重置环境。
operator 是本地实验记录，不是经过身份认证的用户账户。
会话是进程内对象，程序退出后不提供故障现场持久恢复；JSONL 用于审计和复现。

## 范围

本次完成的是近期四智能体协同与接管状态机原型。控制策略仍是动作空间中点基线，
有限目标模板不是通用任务规划器，单角色单候选不是多执行者竞价部署。
没有实现 mAbEnv 适配、训练型 R-03、多模态模型、认证式人机界面或完整工艺目标控制。
不能由这些接口验收推导“效率提升20%”、工艺安全或工业 L3 已达标。
