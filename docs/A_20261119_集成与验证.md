## 数值目标主链

安装 `requirements.txt` 后在仓库根目录运行：

```sh
python -m l3_system.main --environment AtropineEnvGym --seed 1101 \
  --goal-spec configs/goals/atropine_goal_regression.json \
  --goal-registry configs/goals/atropine_model_registry.json \
  --goal-timeout 60 --output outputs/a19-atropine
```

[回归目标](../configs/goals/atropine_goal_regression.json) 采用无量纲 E-factor 区间 [12, 15]，在既有公开 Atropine 中点基线附近选取，用于复核目标链路。步数预算为 5，连续 2 个有效 post-step 样本才达成。这个区间用于仿真回归，生产目标和工艺围栏另行验收。默认 Atropine 中点策略用于两个动作分支，尚未测量从区间外恢复到区间内的控制性能。

本地实测 seed 1101，两步后达成。计划依次为 `hold_target`、`hold_target`、`report_achieved`，各轮调用 step 数为 1、1、0。每个周期记录计划及父计划、C 授予、D 审核、B 的请求与结果以及最后的目标复核。生成的 `result.json`、`events.jsonl` 和 B/D 日志保存在指定输出目录。实测结果文件由上述命令重建，任务 ID、时间等随运行变化。

执行前校验观察版本和时间预算，并检查已经转换为 B 请求精度的候选是否在 GoalSpec 动作范围内。结果关联 task、subtask、request 和执行后状态版本。错误结果阻断后续周期，未对账的 step 禁止自动重放。时间预算从目标会话开始计时，在派发及后续评估时检查，已进入求解器的调用不会被抢占。现有旧任务和本地候选替换仍由原有运行入口支持。

## 环境与界面

CLI 支持选用 Atropine 或已安装的 B03 mAb 适配器和 B03 执行器。mAb 使用 B03 验证脚本中的稳态参考动作。将 B 提交的 `l3_system/execution` 原样覆盖到隔离测试副本，按该提交的 MPCTools 源及补丁安装后，在 seed 1610、模型步预算 2 上完成一次本地四智能体周期。记录一次 step，调度锁已释放。通用中点动作对 mAb 的初次试跑返回环境错误，因此默认切换为 B 的稳态参考。mAb 数值目标现在支持 B03 固定配置的 `physical_projection` 字典。A 用 B 的 `xscale` 计算用于目标评价的物理观测，用 B 的 `action_coordinates.to_physical` 检查候选动作是否满足 GoalSpec 的物理范围。控制策略、D 审核和 B 执行均接收原模型坐标。A 在开始时检查环境、B03 版本、归一化设置、坐标名称及投影形状。其他坐标组合会报错。

### mAb 数值目标复现

本次追加以 [PR #10 的原提交 d8296c7](https://github.com/W-create-user/L3-/commit/d8296c7f1adcb58ba395d4a529e111df69684920) 为父提交。在隔离副本中原样读取并载入 [B03 dd76cea](https://github.com/W-create-user/L3-/commit/dd76ceafb1f1b331660d3a171cbcd087fd0b7559) 的 `l3_system/execution`、`configs/environments/mab_physical_registry.json` 和 `configs/controllers/mab_buffer_pi.json`。MPCTools 使用 B 的固定源码与补丁，其他依赖按仓库要求安装。独立运行：

```sh
python -m experiments.verify_a_mab_goal \
  --registry configs/environments/mab_physical_registry.json \
  --b-config configs/controllers/mab_buffer_pi.json \
  --output outputs/a19-mab-numeric
```

验证采用 B 研究配置的缓冲罐液位设定点与容差 [14.95, 15.05] dm、连续有效 3 步、上限 10 步、seed 1610。动作采用 B 提供的稳态参考，PI 配置只提供本次回归的目标、步数及种子。初始条件与这个试验仅用于验证稳态保持及坐标衔接。实际结果为 `succeeded`，3 次仿真 step，达成报告 0 次 step，各轮调度锁均释放。A 的结果会记录目标评价使用的物理样本，并保留 B 原坐标的请求和执行结果。此次交付的 mAb 运行依赖 B03 执行器已经装入同一测试副本。

C 的可见代码仍为本地调度入口，未找到可直接联调的 ZeroMQ 实现。跨进程取消、迟到反馈和生产目标验收继续单列。

```sh
python -m l3_system.ui.app --output-dir outputs/a19-console
```

访问 http://127.0.0.1:5000，查看环境、状态、最近任务、阶段结果、监管判定、最新观测和接管记录。执行和人工确认恢复均走 A 的会话方法。用表单凭据和表单版本阻断缺少凭据或重复提交的操作。恢复要求操作人、原因、无未结资源或动作请求，以及通过当前状态复核。
