# D03 多事件评估与分母口径

本轮将孤立森林报告从首事件统计扩展为逐事件评估，保持原有训练和验证阈值选择流程不变。新增指标只评价固定模型预测，不用测试事件结果调整阈值。没有新增真实工艺数据或研究效果结论。

## 事件与窗口不是同一个分母

EventEvaluation/1.0以原始逐条布尔标签中连续true的最大区间定义一个事件。两个区间只要中间有false，就仍为两个事件，即使滑窗标签因重叠而连成一片。只有布尔标签时，不能区分同时发生、时间重叠的不同物理故障；需要独立event_id时须后续扩展标签接口，不能声称本函数已完成事件根因拆分。

窗口预测映射到该窗口的结束记录。每个原始事件只接收发生在其起止区间内的预测；事后滑窗仍含异常历史而报警，不算及时检出已结束的事件。延时等于首次有效检出记录减真实起始记录，单位为交互记录，不是物理秒或人工响应时间。

已有窗口混淆矩阵仍按“窗口内至少一条原始标签为异常”计算。因此事件结束后的窗口尾部可能计为窗口TP，但不能给原始事件补记检出。两种口径分别保留，不相互替换。

## 暖机与漏检

首个完整窗口在window_size-1号记录结束。若整个事件发生在此之前，该事件记为unscorable，不记为检出或零延时，也不静默归为普通漏检。若事件持续到首个窗口之后，则延时仍从真实起点计算，并标注onset_before_first_window。

每个事件保存start_record、end_record、scorable、eligible_start_record、first_detection_record、detected、missed、delay_records。可评分而未检出的事件记missed=true，delay_records=null；不可评分事件单独列出。以scorable_event_recall报告检出/可评分事件，同时必须展示所有事件数与不可评分数，不能只引用比例隐藏暖机缺口。

## 集合汇总

每个验证/测试episode分别保存event_evaluation；集合event_summary保留：

| 分母 | 字段与含义 |
|---|---|
| episode | episode_count；全正常episode数及其中发生报警的episode数 |
| 原始事件 | event_count、scorable_event_count、unscorable_event_count、detected_event_count、missed_event_count |
| 窗口 | window_count、normal_window_count、false_alarm_window_count；仍与原窗口混淆矩阵并列 |
| 有延时的已检出事件 | detected_events_with_delay及mean_delay_records_among_detected |

平均延时仅覆盖已检出的事件，必须连同漏检和不可评分数量报告。全无异常事件时事件召回为null；全无检出时平均延时为null，不能填0表示即时响应。空集合也显式保留0个episode和null比率。窗口互相关联，不作为相同数量的独立研究样本。

first_event_delay_records等旧字段仍保留，但新卡片的语义依据raw事件区间，新增first_event_unscorable区分暖机不可评分。旧模型卡中按滑窗扩张区间计算的首事件统计与新口径不能直接混合比较；读取新卡片以EventEvaluation/1.0为准，不改写已有历史模型卡。

原有anomalous_episode_missed字段仍按“整episode没有任何异常窗口命中”定义，不能用它替代逐事件漏检数量；例如只有事后尾部窗口命中时，此字段可能为false，但原始事件仍记missed。事件级结论以event_evaluation及event_summary为准。

## 验证

新增12项确定性评估测试：首事件检出但后续漏检、原始起点延时、事后尾部不补记、近邻事件不合并、暖机不可评分、跨暖机事件、正常episode误报、无检出、不同分母汇总、错误输入、空集合和末条事件。

D01本地测试157项、系统回归124项。原模型训练测试同样运行，验证新评估器已进入fit生成的卡片。测试序列是合成夹具，未将数值数据或模型权重上传。正式B05标签与实验数据仍需独立依据及共同分集确认。
