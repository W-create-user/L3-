# D03 离线观测故障回放工具

本工具将前一轮采集草案中的SENSOR族推进为可运行代码。只读取D01规范化轨迹的observation_before，对副本执行缺测、卡值、偏置或漂移，保留未修改参考、来源组和独立注入记录。不会调用仿真reset/step，不改变执行历史，不启用R-03，不训练模型。

本轮验证包含两部分：24项新增单元测试使用临时合成夹具；另在本地读取B提交 `c3dc5cc12d5f5bdd2ae39673bcf74529a24912d3` 的continuous_5记录，核对转换后5条观测，在第1至第3号记录的obs[6]副本设置缺测，3条均触发STATE-INVALID完整性拒绝。源文件未改变，新增仿真调用为0。该结果只是离线缺测契约验证；并未生成工艺异常真值或证明模型识别能力。本次代码提交不包含收到的或派生的数值轨迹。

## 已实现的四种机制

| kind | parameters | 区间内的操作 | 标签与检测边界 |
|---|---|---|---|
| missing | 空对象 | 目标坐标为null，available_mask对应位置为false | 可用于完整性拦截检查；不使用非法JSON NaN |
| stuck | reference_record | 固定为未修改参考序列中指定记录的值，参考不能晚于事件开始 | 注入生效时可能暂未改变数值；不保证能从单点判断故障 |
| bias | offset | 加一个非零有限偏置 | 有限数值可能通过完整性检查；不代表已识别异常 |
| drift | increment_per_record | 加 `increment_per_record × (sample_index-start_record+1)` | 按交互记录递增，单位为源坐标单位每记录；不是每秒漂移率 |

start_record、end_record均为从0开始、包含两端的交互记录编号，不是物理分钟或env.step次数。区间外恢复为参考序列。同一坐标的重叠事件会被拒绝，避免未经定义地叠加不同故障；不同坐标可以同时注入。单位和坐标必须与字典一致，工具不自动换算、不为未知物理单位背书。

“参考/clean”仅表示注入前的数据副本通过数值完整性检查，不能读成“已确认工艺正常”。这里的故障标签表示合成测量机制活跃，不表示真实工厂故障，也不表示每个活跃记录都已经产生可观察差异。

## 输入与运行

脚本为 [sensor_fault_replay.py](../deliverables/D01/scripts/sensor_fault_replay.py)。输入需要：单一episode且通过D01内容检查的JSONL、D01Variables/0.1字典、一个SensorReplay/0.1注入规格。当前限定Atropine的39/4结构，不接受mAb直接套用。

可以先用已有review_b_handoff.py在本地转换B包；原始B包与生成的轨迹仍留在本地。规格起点为 [sensor_replay.example.draft.json](../configs/research/sensor_replay.example.draft.json)，其中零哈希会被拒绝，必须换成实际输入文件的SHA256，并填入真实episode和已核对来源组。默认source_split=excluded，不自动进入训练。

```bash
python deliverables/D01/scripts/sensor_fault_replay.py \
  --source LOCAL_REVIEW/continuous_5.jsonl \
  --dictionary LOCAL_REVIEW/observation_action_dictionary.structure_only.json \
  --spec LOCAL_REPLAY/spec.json \
  --output LOCAL_REPLAY/output_NEW
```

这些LOCAL路径是使用者提供的本地文件，不是仓库预置数据。输出必须是新目录；不会覆盖已有输出或源文件。工具核验输入哈希、D01内容、episode及顺序、变量单位/坐标、事件区间和参数。无效规格、非有限值、数值溢出、未来卡值参考、源文件变化和坐标重叠均拒绝，不生成可冒充正常样本的填充值。

## 结果分开保存

| 文件 | 内容与用途 |
|---|---|
| clean_inputs.jsonl | 未修改的参考观测与可用mask |
| replay_inputs.jsonl | 注入后的观测与可用mask，缺测为null |
| labels.jsonl | 活跃事件ID、合成测量故障标记；process_anomaly_label始终null |
| integrity_checks.jsonl | 原STATE-INVALID谓词对参考和注入后观测的检查结果 |
| provenance.json | 源数据、字典、规格、生成器和输出哈希；来源组和原分集；事件参数 |
| summary.json | 数据完整性拒绝、活跃故障仍通过等计数，以及未训练/零模型调用声明 |

输入文件不复制reward、执行状态、failure_reason、D结论或故障ID。sample_index仅用于对齐，不能作为泄露固定故障时段的分类特征。labels与integrity_checks都不作为模型输入，provenance中的事件参数也不是特征。

派生输出沿用输入声明的lineage_group和split，不增加独立episode数量，不自动产生train/validation/test划分；输入声明是否正确仍需人工复核。即使源split写train，输出也保持accepted_for_training=false，不能自动进入Isolation Forest的正常训练子集。改变来源组、使用输出文件名中的故障类型、把重叠窗口分到不同集合都可能泄漏。

## 完整性与异常识别分开

本轮将原MonitoringAgent.observation_error中的完整性谓词提取为共享的纯函数observation_integrity_error；在线D审核仍调用同一个判断，行为保持一致。离线工具因此无需构造虚假的live action_space，也不生成可授权执行的SafetyDecision。

偏置、漂移、卡值只要仍为正确维度的有限数值，就可能通过该谓词；summary会记录fault_active_integrity_passes。这个数字不是误报/漏报科研结果，也不是模型准确率。学习模型尚未接入，没有工艺异常预测或置信度输出。

## 验证及下一步

D01测试120项通过（前96项加24项回放测试）；系统回归124项通过。新增测试涵盖四种机制、输入不变、标签隔离、分组继承、哈希、拒绝覆盖、参数错误、溢出、命令行与零reset/step调用。

后续D03仍需要有独立正常依据的多步轨迹、验证/测试来源组及足够覆盖度；再训练Isolation Forest、用验证集确定阈值并在冻结测试集评估。该工具提供的是离线测量故障构造与数据质量检查，不能替代B的真实过程扰动设计或证明闭环恢复效果。
