候选版集成 A 主线、B 的回执边界和 C 的 ZeroMQ 交付。基础主分支是 `5838f0f9b14e80fcd3d53a7895363f5ce854f6d1`，B 来源为 `b480effd96f6045e3948befda2eaddd3a9ce7f9c`，C 来源为 `9eb1f5be692b9230ac2e6bbce2d400ed070a2d68`。发布分支保留来源提交。D 已合入的模型审核用于研究验证，D 新学习门控另列。代码中的暂停只控制仿真会话。

## VS Code 清洁环境复现

从待验收分支根目录操作。完整验证环境为 Linux 或 Windows 上的 WSL，Python 3.12，Git 和本机 libzmq（Ubuntu 包 `libzmq5`）。Windows 原生 PowerShell 可先验证本地 Atropine 和 Flask。

```bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-a-release.txt
python -m experiments.setup_a_mab
python -m experiments.verify_a_release --output outputs/a-release-01
```

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m experiments.verify_a_release --profile local --output outputs/a-local-01
.\.venv\Scripts\python.exe -m l3_system.ui.app --output-dir outputs/a-console-01
```

完整验证从公开依赖安装 MPCTools 和已知 SHA-256 的历史兼容补丁。结果目录应使用新名称。查看 `report.json` 中的退出码、各用例原始日志和 `SHA256SUMS`。零退出码表示所选验证用例通过。下面是各路径的独立启动命令。

```bash
python main.py --cycles 3 --output outputs/a-local
python main.py --transport zmq --output outputs/a-zmq
python main.py --environment MAbEnvGym --seed 26001 --max-steps 10 --goal-timeout 90 --goal-spec configs/goals/mab_public_buffer_goal.json --goal-registry configs/goals/mab_public_buffer_registry.json --output outputs/a-mab
python -m l3_system.ui.app --output-dir outputs/a-console
```

ZeroMQ 命令运行固定的 Atropine 联调场景，包括四进程正常执行、重复和冲突请求、C 退出、恢复及审核拒绝。mAb 命令运行公开稳态液位目标；带偏置和故障回执使用完整验证中的 `mab-receipts`。Flask 通过本机 `http://127.0.0.1:5000/` 查看和操作。演示顺序为正常周期、暂停、确认接管、填写操作人与理由恢复、再次运行。运行日志关联任务、授予、审核和步进，界面演示用同一状态机。

本轮 Linux 验证的 13 项命令均通过。核心测试发现 242 项，其中 240 项通过、2 项依赖未公开 B05 配置而跳过。额外通过 10 项 C 专项测试。真实 mAb 稳态目标 3 步达成；带模型审核的回执用例通过 11 种检查和 3 步全链冒烟。公开开发组另复跑 120 次并审计 420 步，C 的 90 次调度复跑指标与原发布文件逐字节一致。Flask 七项真实环境 HTTP 交互已核验，另在 Chromium 实际验证了暂停、确认接管、恢复和重新执行。12 秒演示视频已归档，独立操作者仍待签字。[机器可读实验摘要](../evidence/a_20261127/release_verification.json)
