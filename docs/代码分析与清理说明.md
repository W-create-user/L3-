# 代码分析与清理说明

## 发现的问题与修复

原始仓库基线提交：`f418be7`。既有代码已经具备 Atropine 单步仿真与部分集成能力，本次在这些实现上整合与修复。

| 原问题 | 当前处理 |
|---|---|
| 根入口默认 legacy，另有 a-final；两套 A/C/D 与编排并行维护 | 统一为 `main.py` → `l3_system.main` |
| 调度、决策、监管跨目录使用 sys.path 和动态加载，依赖成员快照 | 所有角色与适配器集中于同一 Python 包，使用明确包导入 |
| 新编排只保护 B 的执行异常，读取、动作生成、监管异常可能遗留 C 锁 | 所有阶段统一异常到失败反馈，释放锁，下游 blocked，A 收到总任务结果 |
| 父任务反馈编号未与已注册子任务核对 | C 拒绝错误 parent task_id 的反馈和状态查询 |
| 审核适配会丢掉 approved/status 的矛盾信息 | 检查矛盾、演示模式与请求编号后再传给 B |
| 动作生成与审核失败后可能遗留待执行请求 | 新增 B 取消接口，失败终态取消候选，无环境推进 |
| 假设两个角色都能做同一工序的配置投标 | 只让已安装且具备能力的角色投标，不声称实现了真实多设备竞争 |
| 启动依赖硬编码的 D 盘路径和成员目录 | 使用项目虚拟环境与统一 vendor，支持显式环境路径 |
| 超大依赖清单包括训练、文档、CUDA 和标准库重复项 | 仅 7 项直接运行依赖，另存本次完整锁定版本 |
| SMPL 导入 utils 时强制导入 torch 和整个 mzutils | torch 数据集导出延迟导入；内置原 mzutils 两个归一化函数并保留 MIT 许可证，工艺方程不变 |
| 两项旧测试缩进错误，没有进入 unittest 收集 | 修正并纳入统一测试集 |

## 清理范围

- 删除 `integrated_system/` 旧编排、`决策智能体/` 旧 A、`agents/` 旧 D、`C_member_before_20261108/` 旧 C。
- 删除 `执行智能体.zip` 和 `执行智能体/` 中的成员交付、外部 D 拷贝、嵌套 A、旧采集脚本和旧演示；将仍需使用的六个 B 运行模块迁入 `l3_system/execution/`，保留关键 B 契约测试。
- 将完整上游 SMPL 从嵌套成员目录移至 `vendor/smpl/`。mAbEnv 及相关模型文件保留，支持后续主要研究路线。
- 删除旧入口专用测试、旧实验脚本、旧交付文档和重复历史 `evidence/`，以本次重新运行的 `evidence/current/` 为准。旧记录仍可从基线 Git 历史恢复，当前 ZIP 不包含旧记录。
- 替换过期的运行说明、事实核验清单和进度表，重新生成当前代码与证据的对应说明。

SMPL 上游版本与原始哈希见 `vendor/smpl/SOURCE_VERSION.json`；本地改动见 `vendor/LOCAL_CHANGES.md`。完整变更补丁与清理前文件列表随交付提供。
