# 四类智能体统一运行入口

已集成仓库实际 A、C、B、D 模块与真实 SMPL AtropineEnv。统一主程序位于仓库根目录 `main.py`；原成员目录保留。当前是本地同步、有限模板和中点测试策略，不是工业 L3 达标或优化控制实现。

## 安装和运行

需要 Python 3.11。在仓库根目录运行：

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r .\执行智能体\code\requirements-lock.txt
.\.venv\Scripts\python.exe .\main.py --scenario normal
.\.venv\Scripts\python.exe .\main.py --scenario reject
.\.venv\Scripts\python.exe .\main.py --scenario inspect
```

本机也可直接运行 `powershell -NoProfile -ExecutionPolicy Bypass -File .\run_system.ps1`。脚本优先使用 SMPL_PYTHON，再使用本目录 .venv，最后尝试现有本机环境。换电脑必须安装依赖，不复制虚拟环境。

normal：六个子任务 completed、step_delta=1；reject：预期总任务 failed、failure_reason=safety_rejected、step_delta=0；inspect：三步 completed、step_delta=0。拒绝是演示预期，不是控制任务成功。

每次输出 `outputs/four_agents/新目录`，含 A_task、C分配/Bid、D原始审核、B执行、CSV和 A_feedback。运行日志保留旧库 warning，以退出码和 result.json 为准。

```mermaid
flowchart LR
 A[A 目标和模板任务] --> C[C 依赖就绪和CNP分配]
 C --> B[B 观测和候选动作]
 B --> D[D 实际规则审查]
 D -->|pass| E[B 校验后step]
 D -->|reject| F[B 拒绝且不step]
 E --> G[C 更新任务和资源锁]
 F --> G
 G --> H[A 反馈收件和完成核验]
```

## 关键接口

`integrated_system/system.py` 内 DecisionCoordinator 包装实际 A 的任务生成并补齐反馈收件；MonitoringGateway 包装仓库实际 D.check_action 为 check_request，保留 raw_review。未假设根目录 D 已经有 check_request。

A 的状态有效性检查和结果核验由集成层提供，不宣称大模型推理。C 的每个获奖者在执行前校验，依赖未完成的节点不执行。B 候选先准备，D审核后再 execute_action，B 再验证请求/状态版本。B 的 execute_assignment 更新为已交付版本；原低层接口继续兼容。

## 实验与检查

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -p test_four_agents.py -v
.\.venv\Scripts\python.exe .\experiments\run_system_validation.py
```

实验脚本要求 `evidence/four_agents` 不存在，避免覆盖原数据。重新实验请在新工作副本运行，或先归档该目录并保留旧数据；不要删原数据后伪称首次运行。测试可反复运行，临时目录自动隔离。

已保存最终批次：3个正常四角色任务、3个匹配单执行模块任务（合计6次真实step），3个拒绝任务（0step）、1个只读任务（0step），40个离线边界候选。初次批次保存在 `evidence/four_agents_initial`，不混算为最终批次的新样本。

8项新增集成测试、C的16项及既有59项回归检查通过。配对状态和reward一致，本机四角色耗时更长；不声称效率提升。C原30组合成对照继续保持合成标注。未使用真实危险输入做无监管执行。
