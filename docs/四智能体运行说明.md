# 四智能体运行说明

## 安装与入口

建议 Python 3.11/3.12。按根目录 README 创建虚拟环境并安装 `requirements.txt`，无需 PyTorch、CUDA、mzutils 或训练依赖。SMPL 源码、Atropine 初态与模型随仓库提供，无需下载外部模型。

Linux/macOS：`python main.py --scenario normal`。Windows：`powershell -File run_system.ps1 -Scenario normal -Cycles 1`，脚本使用项目 `.venv`，也可通过 `SMPL_PYTHON` 指定解释器；Windows 脚本本次未在 Windows 实机测试。

| 参数 | 行为 |
|---|---|
| `--scenario normal` | 完成六阶段控制链，真实推进一步 |
| `--scenario reject` | 构造越界候选，D 拒绝，真实步数为零 |
| `--scenario inspect` | 读取、评估、返回状态，真实步数为零 |
| `--cycles 5` | 同一环境连续运行五轮，每轮新任务，不重置工艺状态 |
| `--seed 1101` | 初始化随机种子 |
| `--max-steps 60` | SMPL 自身回合参数，遵循上游终止口径 |
| `--output-dir outputs/my-run` | 保存到新的目录；已存在时拒绝覆盖 |
| `--offline-preview` | 仅输出规划，不初始化环境 |
| `--source-dir /path/to/smpl` | 指定 SMPL 源码；也可设置 `SMPL_SOURCE_DIR` |

上游 Atropine 在自增计数前判断超时，因此 `--max-steps 1` 可能返回两次推进结果；适配器如实保留上游 done/timeout，并在其返回终止后阻止继续推进。

连续运行遇到终止或失败会停止，未完成请求轮数时 CLI 返回失败。每一轮结果都保存，即使 SMPL 最后一次成功步触发回合终止也不会额外推进。

## 四个角色及数据契约

| 角色 | 源码 | 输入与输出 |
|---|---|---|
| A 决策 | `l3_system/decision_agent.py` | 字符串/字典目标 → 带唯一 task_id、subtask_id、依赖、前置条件与完成判据的 Task |
| C 调度 | `l3_system/agents/scheduling_agent.py` | Task、Bid → Assignment；终态 Feedback 释放执行者锁 |
| B 执行 | `l3_system/execution/execution_agent.py` | 观测与候选动作 → 带 request_id、state_version 的 ActionRequest；审核后返回执行结果 |
| D 监管 | `l3_system/agents/monitoring_agent.py` | ActionRequest → SafetyDecision（pass/reject、规则、原因、风险级别、请求身份） |

`l3_system/main.py` 管理六个实际阶段：观测 → 状态有效性检查 → 准备候选 → D 前置审核 → C 授予后的 B 执行 → A 核验反馈。只读任务使用三阶段模板。

每个阶段都独立交给 C 调度。CNP 完成发布、收集投标、评分、授予、结果反馈；当前每类任务只配置一个真实且具备能力的本地角色投标，没有虚构备用执行者。CNP 支持多投标评分和失败后重新授予，相关接口通过测试；主运行链没有可替代的真实执行设备，因此失败会返回 A，停止下游，不自动重做可能已执行的动作。

B 在动作准备时不推进环境。D 前置审核后，执行前再次审核同一个候选；B 检查请求内容未改动、版本未过期、请求未使用过。拒绝、缺失/矛盾审核、身份错配、异常、非有限动作均不能隐式放行。任务失败后待执行候选被取消，下游标记 blocked。

D 的 R-01 检查动作类型、形状、有限性，R-02 检查真实 Box 动作边界。R-03 工艺状态约束尚未启用；动作边界通过不等于工艺安全获得证明。

## 结果与复查

每次运行保存：

- `result.json`：每轮完整计划、子任务状态、C 分配历史、阶段结果及总计步数。
- `events.jsonl`：授予、模块异常、子任务终态及 A 最终任务反馈。
- `B_events.jsonl`：请求准备、审核、取消和真实环境执行结果。
- `D_reviews.jsonl`：D 原始审核，保留任务和请求编号。
- `run_error.json`：初始化或外层异常时保存具体原因，不把失败写为成功。

`python -m experiments.run_validation --output outputs/validation` 执行 3 个种子的正常/拒绝/只读任务和连续 5 轮共 10 个真实环境场景，并检查结果、真实步数及 C 锁释放。测试替身只用于单元和故障注入测试，不计入真实环境记录。

## 环境适配与后续路线

`EnvironmentAdapter` 封装 reset、observation_space、action_space、get_observation、state_version、step_calls、step、close。核心智能体通过这些接口与环境交互，不使用 39/4 硬编码来生成或验证动作。mAbEnv 仍需单独实现初态、动作单位/缩放、终止条件和跨工序任务模板，并安装对应控制库、验证工艺约束；仅保留 mAbEnv 源码不能视为适配完成。

上游 Gym 0.26 的维护提示和 CasADi 的旧积分器选项提示不影响本次运行。保留 Gym API 是为了与固定版本的 SMPL 兼容。

## 持续核对

新增固定顺序调度基线和三类最小对照，复现方法见 [实验说明](实验说明与指标.md)。C 对重复终态反馈作幂等处理，拒绝冲突终态；父任务依赖需其全部注册子任务完成。返回结果会把环境提前结束导致轮数不足标记为 incomplete_or_failed，而非只返回最后一轮的完成状态。
